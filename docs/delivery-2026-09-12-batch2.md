## 一、需求逐项落实

### 1. 中英双语（页面右上角切换）
- UI 文案：vue-i18n 9.14.5（版本锁定），`src/i18n.js` 双语语言包，顶栏按钮一键切换，
  偏好持久化 localStorage；Element Plus 组件语言跟随。
- 内容级：18 个 Mock 案例全部补充英文（题干、选项、诊断摘要、知识点名、案例标题、
  行为说明、样例提示 note_en——样例注释经真实 LLM 批量翻译 72/72 落库）；判分反馈
  双语输出（`feedback` / `feedback_en` 计数一致，测试断言）；教师端同样双语。
- 内容缺失英文时自动回退中文，旧问卷数据仍可显示。
- 公式排版：`$…$` 标记的数学/变量以 **Times New Roman 衬线**渲染，`` `…` `` 代码片段
  用等宽字体；`FormulaText.vue` 组件统一渲染，展示文本由补丁脚本自动加注。

### 2. 流程说明优化
- 首页"流程说明"由纵向 el-steps 重设计为五张自绘步骤卡片（编号 + 图标 + 标题 + 描述，
  hover 抬升），双语；首页整体重排：渐变 hero + 双入口卡片。

### 3. 整体 UI 美化
- 学术靛蓝主色（#4f6ef2）对齐 Element Plus 主题变量；卡片圆角/阴影统一；顶栏毛玻璃
  置顶；公式 Times New Roman + 代码 JetBrains Mono 的排版层次。

### 4. 代码高亮 + 左右独立滚动
- 代码面板接入 highlight.js 11.12（C 语言关键词/字符串/注释着色），替换原手工配色；
  题目标注行、聚焦行高亮保留。
- 桌面端左（代码）右（题目）两栏独立滚动：代码列 `position: sticky + overflow-y:auto`，
  题目列随页面滚动；教师详情抽屉代码同样使用高亮组件。

### 5. 接入真实 API
- 模型：**ark-code-latest**（火山方舟 coding 网关 `https://ark.cn-beijing.volces.com/api/coding/v3`，
  OpenAI 兼容协议）。Key 存放在 `.env.local`（已 gitignore，不入库），`LLM_MODEL`
  默认 `ark-code-latest` 可覆盖。
- 修复冒烟中发现的集成缺陷：真实模型不回显 `student_id`/`assignment_id` 导致校验失败
  → 后端权威注入（`agent.py` / `evaluator.py`），不信任模型回显。
- 新增 `AA_OUTPUT_LANG=en|zh` 环境变量控制真实模型的学生可见文本语言。
- 端到端冒烟通过：真实生成 5 题问卷（诊断"提交完全正确"）→ 真实评价
  （understanding/score/逐知识点/双语反馈齐全）。
- 推理型模型适配：`max_tokens=8000`、180s 超时、空输出视为失败触发重试。

### 6. 代码变异题（点击题目左侧代码联动）
- 新题型 `code_variant`：题目携带 `variant={line_no, replacement}`（"假设把第 N 行改成
  XXX"）。18 个案例各新增 1 道（共 18 道，答案字母位置已打散），例如 C03："把第 4 行的
  `i <= n` 改成 `i < n` 会怎样？"。
- 学生点击该题 → 左侧代码面板即时展示修改后代码：改行绿色高亮 + "改"徽章，原行删除线
  幽灵行 + "原"徽章；点其他题恢复。
- 判分：与选择题一致（`exact-choice`）；`variant` 学生可见、答案永不下发（public 视图
  与泄漏测试覆盖）。72 组预置作答全部补齐 q5 并按判分引擎重算 expect，四档语义
  （mastered/partial/limited/insufficient）逐一保持。

### 7. 重新作答加载上次答案
- `GET /api/exam/{sid}/result` 的 `attempts[]` 现包含本人历次 `answers`。
- 重新进入答题页：同一问卷版本下，无本地草稿的题目自动预填最近一次作答，顶部提示
  "已载入你上次的答案（第 N 次作答）"，可一键"清空重填"；版本不同则不预填（防错配）。

### 8. 限时功能
- 问卷携带 `time_limit_minutes`（Mock 案例默认 20 分钟，0 = 不限时）。
- 答题页倒计时条（≤5 分钟变黄、≤1 分钟变红），归零自动提交（免确认）并标记
  `time_expired`；提交携带 `duration_seconds` 供教师查看；学生结果页与教师详情、
  作答下拉框均标出超时提交。
- 已知限制：限时由客户端时钟执行、服务端只记录不拒绝（硬约束需服务端计时，见未完成项）。

## 四、未完成项 / 已知限制

- **限时为软约束**：信任客户端时钟；需防作弊时应改为服务端下发开始时间并在提交时校验。
- **EN 内容覆盖**：C01–C06（演示学生案例）的 text 样例补充了英文变体（"I don't know"）；
  C07–C18 的英文 text 回答会落入 `uncovered` 转人工核验（符合规则，但英文学生用这些
  案例时体验是"待核验"）。补齐需为每案例样例增补英文变体。
- **真实 LLM 评价质量**：仅完成端到端功能冒烟，判分质量未做系统评估（模型输出波动、
  温度策略、结构化 schema 约束可进一步收紧）。
- **公式组件为轻量实现**（标记渲染），未接入 LaTeX/KaTeX；当前题目为代码语境，
  无复杂数学公式需求。
- 双语界面下教师复核反馈由教师手工输入，系统不翻译（真实内容保持原语言）。
