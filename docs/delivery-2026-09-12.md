## 一、修改清单（按工作包）

### WP1 评价规则与版本关联约定
- 新增 `docs/evaluation-rules.md`：代码质量 × 理解程度两维正交（四象限）、
  KnowledgePointResult 四要素、初答/追问两阶段、版本关联 7 条硬约束
  （409 旧版本提交、submission_token 幂等、按学生文件锁、启动恢复）、
  聚合阈值（≥0.9 mastered / ≥0.6 partial / ≥0.3 limited；未覆盖封顶 partial 且强制复核）、
  鉴权可见性、学生状态机、TA 复核闭环、Mock 匹配规则、逐条实现映射。

### WP2 Mock 案例库与判分引擎
- 新增 `app/cases.py`：代码归一化指纹（与学号无关）、`data/mock_cases/` 加载、
  未覆盖代码 → 通用问卷（诊断注明"演示规则未覆盖该代码，待人工核验"）。
- 新增 `app/mock_grader.py`：确定性判分。选择题 `exact-choice` 精确匹配；text 题
  `sample-match` 与预置样例变体精确匹配（全半角标点归一）；未命中 → `uncovered`
  待人工核验（不靠字词重合率宣称语义理解）；仅无样例的通用问卷 `heuristic` 兜底
  并强制 `needs_ta_review`、置信度降至 0.5。
- 新增 `data/mock_cases/C01–C18.json`：18 种典型代码（含正确实现、`i<=n` 越界、
  哨兵值 -9999、`arr[1]` 初始化、跳过 `arr[1]`、`i<n-1`、返回下标、提前 return、
  返回首个变量、排序副作用、复合错误等），每案例 4 组预置作答
  （mastered / partial / contradictory / insufficient），共 **72 组**，期望结果逐一在
  `tests/test_mock_cases.py` 断言。C01–C06 沿用原 6 名演示学生的题目文本（向后兼容）。
- `app/llm.py`（Mock Provider）：诊断改为从提交 prompt 提取代码后按内容匹配案例；
  评价改为调用判分引擎（GRADING_DATA_JSON / CASE_META_JSON 行式传递，规避贪婪正则）。
- `app/agent.py`：案例绑定（code_fingerprint / case_id / case_match）由服务端权威写入。

### WP3 闭环缺陷修复（P0 + P1）
按审批 P0 清单逐项：
1. **未认证教师详情 200 + 泄漏 expected_answer** → 新增 `app/auth.py`：全部 `/api/*`
   （除 `/api/meta`）要求 `Authorization: Bearer`；教师口令（`AA_TEACHER_TOKEN` 环境变量，
   未配置时演示默认值 `ta-demo-token`）放行全部，每生访问码
   （`data/access/tokens.json` 自动生成，教师详情页可见）只能访问本人，跨学号 403。
2. **评价失败仍显示旧结果** → 提交与评价分离：答案先落盘（attempt 先建），评价以
   `EvaluationRecord(status pending→ok/failed)` 独立记录；失败时学生端显示"评价失败可重试"，
   教师总览不再用旧评价冒充；`POST /api/exam/{sid}/evaluate` 重试不新增作答。
3. **重新生成后旧答案错配新题** → 重新生成产生新 `version`，旧问卷归档至
   `generated/history/{学号}_v{n}.json`；attempt 绑定 questionnaire_id+version；
   旧版本提交 → 409，前端弹窗引导刷新。
- 幂等：客户端 `submission_token`（前端 sessionStorage 持有，重试复用），重复/并发
  提交返回同一回执（测试含 ThreadPoolExecutor 并发用例）。
- 启动恢复：lifespan 中把中断的 pending 评价标记为 failed（可重试）。
- 结果查询：`GET /api/exam/{sid}/result` 状态机（submitted / evaluating / eval_failed /
  awaiting_review / feedback_ready）+ 发布后的助教反馈 + 提交记录。
- TA 复核闭环：`POST /api/teacher/students/{sid}/review`（confirmed / revised+理由 /
  published+反馈文字），发布前学生端停留在"等待助教复核"。
- 文件安全：所有写入 `mkstemp` 唯一临时名 + `os.replace`；每学生 `flock`。

## 二、验收过程中发现并修复的新缺陷

1. **反馈题数统计恒为 0**：`app/mock_grader.py` 中把 `(verdict, basis, note)` 元组与
   字符串比较，恒为假，反馈文案"答对 0 题…"与真实判定不符。已修复并新增回归测试
   （`test_feedback_counters_match_verdicts`：具体断言 + 全 72 组计数之和不变量）。
   视觉核验：放大截图逐字确认为"答对 4 题"；数据文件与 API 一致。
2. **手机端代码面板被隐藏**：代码卡片误加 `desktop-only` 类，<768px 时 `display:none`，
   手机学生完全看不到自己的代码（违反"手机顺序展示代码在前"）。已移除该类
   （DOM 顺序即渲染顺序），并把验收脚本 T12 从"DOM 存在性"加强为"可见性 + 位于
   首张题目卡之前"（旧检查因 display:none 元素 rect.top=0 而误通过）。修复后像素级
   验证深色面板存在（y≈300–544），放大图确认含行号与高亮。

## 三、数据兼容方式

- 旧 `data/assignment/`、`data/submissions/` 原样使用；C01–C06 题目文本与旧问卷一致。
- 旧 `generated/`、`responses/`、`evaluations/` 由启动时惰性迁移兼容读取
  （`_migrate_legacy_evaluation` 等）；本期验收全部在 `AA_ROOT=/tmp/aa_accept` 独立
  目录进行，**项目内学生作答与评价数据零改动**。
- `data/access/tokens.json` 首次启动自动生成（教师口令优先取环境变量）。
