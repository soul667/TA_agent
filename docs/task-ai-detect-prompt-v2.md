# 任务：优化出题提示词的「AI 代写排查」规则（规则 9 v2）

> 本任务自包含。执行者从零开始，按本文档即可完成。工作仓库：`/home/axgu/TA_agent`（Python 3.13 + uv，测试命令 `uv run pytest`）。

## 1. 背景

本仓库是一个 C 课程助教系统：出题 agent 读取学生 C 代码提交，生成 3~5 道"验证是否真理解"的个性化问卷。提示词在 `prompts/questionnaire.txt`（唯一事实来源，内容哈希即版本号，改完自动换版本）。

当前规则 9（`prompts/questionnaire.txt` 末尾，版本 `pv-ed3ac0b67916`）原文：

> 9. AI 代写排查：找出代码里"不像本人手写"的痕迹——引入了但完全没用到、与题目无关的头文件，平台/IDE 相关宏（如 _CRT_SECURE_NO_WARNINGS），与整体风格突兀或明显超出课程进度的写法，注释与代码不符，命名或格式机械一致得反常。针对这类位置出"为什么这样写"的问题（text 题优先，expected_answer 写出本人应当能给出的合理解释要点）；存在此类痕迹时问卷中至少 1 道。即使代码完全正确，也要就其中 1~2 处简单但关键的选择（数据类型、边界写法、分支结构、是否用递归等）追问"为什么这么做"。自己写的学生能轻松解释；粘贴 AI 生成代码的学生答不上自己代码的这些地方。

**规则 9 v1 的信号方向错了，需要重写。** 课程教师确认：

- 引入没用到的头文件、`_CRT_SECURE_NO_WARNINGS` 这类 IDE/平台宏、注释掉的代码、调试残留等**低级"垃圾痕迹"，恰恰是人类手写的特征**（从旧代码复制、IDE 习惯带出来的）。现代 AI 生成的代码干净、克制，不会犯这种低级错误。
- 因此 v1 会把真实学生（尤其是 VS 环境复制习惯的学生）误判成 AI 嫌疑，方向必须纠正。

## 2. 任务目标

重写规则 9，使出题 agent 生成的问卷能产生**解释压力**，帮助助教区分"自己写的"与"粘贴 AI 生成的"，同时**不冤枉真实学生**。设计原则（必须体现在提示词里）：

1. **信号只决定"问哪里"，不决定"是谁写的"。** 代码风格特征（无论人类痕迹还是 AI 倾向痕迹）只是选题依据；"是否本人所写"由学生回答质量决定。提示词中禁止出现"该生疑似 AI 代写"类的预设定性。
2. **人类痕迹 ≠ 可疑**。垃圾痕迹（多余头文件、IDE 宏、调试残留、命名不一致、魔法数字）是真实学生的常态，不作为怀疑依据；但它们可以成为中性的"为什么这样写"问题素材——本人写的必然能解释（"我平时用 VS"），粘贴的答不上。
3. **AI 倾向信号**（真正的可疑点，值得优先追问）：
   - 注释：教程式注释（解释显而易见的事）、与中文课程不符的全英文注释、每行注释且语气机械一致、注释解释"为什么"的行文像文档；
   - 完成度：题目没要求的边界/防御全处理了（过度防御）、错误提示异常规范；
   - 超纲：明显超出课程进度的技巧（位运算、指针技巧、函数拆分、宏技巧）而代码其余部分很基础；
   - 一致性反常：命名/格式过度统一、与本人其余提交风格突变、多人提交出现雷同骨架（这条教师端才能看，提示词提一句即可）。
4. **对完全正确的提交同样适用**：就 1~2 处简单但关键的选择（数据类型、边界写法、分支结构、是否递归）追问"为什么这么做"。这是本问卷的主要目的——测理解，AI 排查是顺带产出。
5. 问题形态不变：text 题优先，`expected_answer` 写"本人应当能给出的合理解释要点"；type 只能是既有四种（`single_choice` / `multiple_choice` / `text` / `code_variant`）；不新增字段、不改 JSON 结构。
